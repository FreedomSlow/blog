For the first day in our programming Advent calendar we meet the Elves for the first time,
and we are suggested to solve the problem with the dial rotations. The dial in question
has 100 segments the arrow can point to. The arrow can be rotated to the left and to the
right of its current position. We start at the position 50

One thing to remember here: there's no restriction in how the arrow can move on the dial - however,
when we pass the zero to the right - we start the count from 1, and when to the left - we go to 99.

### Part 1
Provided with the series of left (L) and right (R) turns we have to count the number
of times the arrow landed exactly at zero after some rotation.

The solution here is pretty straightforward as soon as one realizes what has to be tracked on every
iteration - **the current position of an arrow**. And the turns is nothing but the changes to this position:
right turn increases it, and the left one decreases it. The last thing left is to take care of the
**[modulo](https://en.wikipedia.org/wiki/Modulo)** in our problem, we have to start counting over from 1 or 99 when crossing zero, remember?
We can get this by computing the remainder of the position modulo the dial size (100 in our case).
Here's the [implementation](https://github.com/FreedomSlow/aoc2025/blob/master/src/1.py#L4) in python:
```python
lines = read_file("../input/1.txt")

turns = []
for line in lines:
    # We treat the left turn as negative and right as positive
    if line[0] == "L":
        turns.append(-int(line[1:]))
    else:
        turns.append(int(line[1:]))

pos = 50
size = 100
ans = 0

for i, turn in enumerate(turns):
    pos = (pos + turn) % size

    if pos == 0:
        ans += 1

print(ans)
```

### Part 2
The problem becomes a bit more complex - now we have to count **all the times** the arrow has crossed zero
during the rotations. The important question to ask here is: can we somehow understand that we crossed
the zero based on the arrow position? The answer is fortunatelly yes, this happens when the position 
after the turn became negative (red points 1-2) or greater-or-equal than the size of the dial (green points 3-4):

Pay attention to the special point (5) marked in orange - if our starting position was zero that means
we didn't cross anything!

One last thing to keep the track of - think what happens when you make a 500 section turn? If your 
position was $$X$$ then the new position will be $$(X + 500) \mod 100 = X$$, so it actually remains unchanged!
In the end we can just add the full rotations to our count and keep working within the "one circle".
This results in the following algorithm (the input file parsing stays the same):
```python
pos = 50
size = 100
ans = 0

for i, turn in enumerate(turns):
    start_pos = pos % size

    # Full rotation
    ans += abs(turn) // size

    # Remaining rotations
    if turn > 0:
        turn %= size
    else:
        turn = (turn % size) - size

    # One circle rotation
    pos += turn

    if (pos >= size or pos <= 0) and start_pos != 0:
        ans += 1

    pos %= size

print(ans)
```

Time & Space complexity of both solutions is O(N) which is pretty nice :)
